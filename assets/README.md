# README media

`demo.webp` is the inline README hero: one continuous session through the product.
The dashboard library, the revenue dashboard, a filter change, **+ Explore** (SQL typed
and run, a bar chart picked in the chart builder, the result added to the dashboard, then
back to the dashboard with the new tile), an AI Studio conversation that pins two tiles, asks for a look in
plain words, asks for section headings, then changes direction in a third message,
and finally the shared metric page reached through the dashboard's info card. It plays
directly on GitHub, with no setup or click-through. `demo-themes.webp` is six stills,
each a fresh copy of the revenue dashboard after one plain-words request to the agent,
with the Studio conversation left open. Pass `--gif` to the capture script for GIF versions; at
8-bit colour they are four times the size and are not committed.

The frames come from the actual app with generated DuckDB data. Studio uses a
visibly labeled **Demo agent** (`scripts/studio_demo_agent.py`), a deterministic
subprocess that reads the request, applies an example theme or inserts section
headings, and narrates what it did. The file edits and the live refresh are real; its text is scripted, not a
Claude or Codex response. Pauses are edited for readability, not model speed.

| Asset | Contents |
| --- | --- |
| `demo.webp` | The product walkthrough, embedded at the top of the README |
| `demo-themes.webp` | Six themes (Neon observatory, Rose quartz, Electric citrus, Morning broadsheet, Ember, Amber terminal), each with the Studio request and reply that produced it |
| `demo-agent.svg` | Separate MCP dashboard-authoring example |

## Re-record

From the repository root, on macOS or Linux:

```bash
uv sync --extra snapshot
uv run playwright install chromium
PYTHONPATH="$PWD" uv run python scripts/capture_studio.py --out /tmp/sqldash-media --gif
```

The script uses a temporary git copy of `examples/studio`, served as the `commerce`
repo of a four-repo workspace next to `growth_marketing`, `platform_observability`
and `finance_ops` (generated by `scripts/showcase_repos.py`, self-contained `VALUES`
dashboards, not committed), so the library scene shows folders rather than one
directory. It seeds a DuckDB table for the Explore scene and isolates its entrypoint
configuration. It checks chart
rendering, JavaScript errors, and that each agent turn wrote the YAML it claims: the
theme CSS, the 12×3 position on the weekday tile, and the three heading tiles. Inspect `studio-demo.diff` and the PNG stills, then check the encoded
WebP for readable text and pacing before copying the two animation files into
`assets/`. The data is relative to the capture date.

Frames are a 1600×1000 viewport captured at 2× (3200×2000 pixels) with a drawn
pointer, eased pointer motion, keyframed typing, and hard cuts on page changes,
so it reads as one session rather than a slideshow and stays sharp on retina screens
even when opened at full size. Anything less than 2× gets upscaled on a retina display
and reads as blurry. The WebP keeps the full render at a fraction of the GIF's size.

`scripts/capture_demo.py` retains the earlier still-frame capture workflow and shares
the sibling repos; use a separate output path to keep it from replacing these assets.
